## 2026-09-24 — Этап 0 (проверка пользователем)

**Сделано:**
- Пользователь прогнал `pip install -e ".[dev,speed]"` и `pytest -v` — все 3 теста зелёные.
- `mlflow ui --backend-store-uri ./mlruns` упал: в mlflow 3.16 файловый backend-store переведён
  в режим "только для чтения", нужен backend на БД (SQLite/Postgres/...).

**Решения (и почему):**
- Локальный backend MLflow — `sqlite:///mlflow.db` в корне проекта, артефакты (trades.csv,
  графики) — по-прежнему в `./mlruns` через `--default-artifact-root`. Так надёжнее и при
  параллельных прогонах сетки на Этапе 7 (SQLite лучше файлового стора переживает конкурентную
  запись из нескольких процессов joblib).
- `mlflow.db` — это локальная инфраструктура запуска, а не константа протокола честности
  бэктеста, поэтому в `config/protocol.yaml` не идёт (файл только про то, что влияет на честность
  результата — комиссии, даты, размер позиции). URI backend-store фиксируется соглашением здесь,
  в JOURNAL, и в командах для пользователя.
- `mlflow.db` добавлен в `.gitignore` (как и `mlruns/`) — это локальный кэш реестра, а не
  часть репозитория; при необходимости реестр всегда можно пересобрать из прогонов заново.
