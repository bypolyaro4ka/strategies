# 05. План работ

Работа идёт строго по этапам. Этап закрыт, когда выполнены все пункты «Готово, если».
`STOP` — агент останавливается и ждёт подтверждения пользователя.
После каждого этапа: коммит + запись в `docs/JOURNAL.md`.

Напоминание: команды (скачивание, установка, запуски) агент **присылает** пользователю,
а не выполняет сам.

## Этап 2. Данные

**Задачи**
- `data/download.py`: 1h klines и история фандинга с `data.binance.vision`
  (запасной вариант — REST API) с `data_start` по вчерашний день. Идемпотентно:
  повторный запуск докачивает только недостающее.
- `data/validate.py`: проверки из `01_PROTOCOL.md`, раздел 4 → `reports/data_quality/report.md`.
- `data/resample.py`: 4h / 12h / 1d по правилам `02_ENGINE_SPEC.md`, 2.3.
- `data/loader.py` с защитой holdout (`02_ENGINE_SPEC.md`, 2.4).
- **Физическая изоляция holdout-данных (второй барьер поверх кода загрузчика):** после
  сборки всех ТФ файлы с барами `open_time >= holdout_start` переносятся в
  `data/processed/_holdout_locked/` (отдельная подпапка с `README.md` "не открывать до Этапа
  8"). `loader.py` читает из обычной `data/processed/` только dev-диапазон; holdout-файлы
  физически лежат в другом месте, так что случайный `pd.read_parquet(...)` в диагностическом
  скрипте или ручной проверке не наткнётся на будущее, даже если кто-то забудет про
  `HoldoutLockedError`.
- Тесты: resample, holdout guard.

**Готово, если:** отчёт о качестве без критичных проблем (или проблемы описаны и
решение согласовано), тесты зелёные, попытка загрузить 2026 год без разблокировки падает
с `HoldoutLockedError`, файлы holdout лежат в `_holdout_locked/`.

**Важно:** скачивание включает 2026 год (данные нужны позже), но загрузчик их не отдаёт.
Агент не открывает и не анализирует эти файлы.

3. `git tag holdout-freeze-v1`, push тега.
4. Агент присылает команду запуска holdout с `HOLDOUT_UNLOCK=1`.
