# 04. Оптимизация параметров, ТФ и монет

## 1. Зачем и в чём риск

Пользователь хочет для каждой стратегии найти лучшие параметры, ТФ и монеты.
Это разумно, но только при одном условии: **выбор делается на dev-периоде 2023–2025,
а 2026 год остаётся нетронутым.**

Если выбирать монеты и параметры по результатам 2026 года и тем же 2026 годом их
оценивать, результат перестаёт что-либо значить. При ~350 конфигурациях × 10 монет
«лучшая» комбинация почти всегда выглядит отлично просто за счёт случайности,
а в реальной торговле такой отбор деградирует.

Поэтому мы делаем двухуровневую проверку:
1. **Walk-forward на dev** отвечает на вопрос «помогает ли вообще оптимизация и отбор монет
   этой стратегии вне выборки». Если отбор монет, сделанный на 2024 году, не удерживается
   в 2025-м, он бесполезен — и мы узнаём это до holdout.
2. **Holdout 2026** — один прогон заранее зафиксированных вариантов.

## 2. Что оптимизируем

| Объект | Как |
|---|---|
| Параметры | Сетка из `03_STRATEGIES.md` (≤ 100 комбинаций на стратегию) |
| ТФ | Входит в сетку как параметр `tf` |
| Монеты | Отбор подмножества пула по правилу из раздела 5 |
| Надстройки | Отдельные варианты с собственной сеткой |

Расширять сетку после просмотра результатов walk-forward можно **один раз** на стратегию,
с записью в JOURNAL (что добавили и почему). Все испытания обеих сеток идут в счёт.

## 3. Три варианта каждой стратегии

| Вариант | Параметры | Монеты | Смысл |
|---|---|---|---|
| **V0** | дефолты из источника | весь пул | «как в книге» — базовая линия |
| **V1** | оптимизированные | весь пул | помогает ли подбор параметров |
| **V2** | оптимизированные | отобранные | помогает ли ещё и отбор монет |

## 4. Walk-forward

Фолды (расширяющееся окно обучения, `config/protocol.yaml`):

| Фолд | Train | Test |
|---|---|---|
| F1 | 2023-01-01 → 2023-12-31 | 2024-01-01 → 2024-06-30 |
| F2 | 2023-01-01 → 2024-06-30 | 2024-07-01 → 2024-12-31 |
| F3 | 2023-01-01 → 2024-12-31 | 2025-01-01 → 2025-06-30 |
| F4 | 2023-01-01 → 2025-06-30 | 2025-07-01 → 2025-12-31 |

Для каждой стратегии и каждого фолда:

1. **Train, портфельный режим:** прогнать все точки сетки на всём пуле.
2. **Выбор параметров (V1)** по правилу плато (раздел 4.1) с ограничением
   `trades ≥ min_trades_train_portfolio`.
3. **Отбор монет (V2):** на train прогнать выбранные параметры в режиме «пара» и применить
   правило из раздела 5.
4. **Test:** прогнать V0, V1, V2 на test-окне. Каждый прогон начинается «с нуля»
   (без открытых позиций); прогрев индикаторов берётся из предшествующих данных — это прошлое,
   так что подглядывания нет.
5. Склеить test-доходности F1–F4 в одну кривую **WF-OOS 2024–2025** для каждого варианта.

### 4.1 Правило плато (защита от случайного пика)

Выбираем не точку с максимальным Шарпом, а точку, у которой устойчиво хорошие соседи:

```
для каждой точки p сетки:
    соседи(p) = точки, отличающиеся от p ровно одним параметром на один шаг сетки
    score(p)  = median(Sharpe(p), Sharpe(соседи(p)))
выбрать p* = argmax score(p) среди точек, прошедших ограничения
```

Категориальные параметры (режим LS/LF, тип фильтра) соседями не считаются —
для них плато считается внутри каждого значения, затем берётся лучшее.

## 5. Правило отбора монет (V2)

На train-окне фолда с уже выбранными параметрами V1:

1. Монета остаётся, если `Sharpe_train > coin_min_sharpe_train (0)` и `trades_train ≥ 5`.
2. Если осталось меньше `min_coins_after_selection (3)` монет → V2 = V1 (отбор не применяется),
   это фиксируется в отчёте.
3. Для S13 отбор монет не применяется.

Отобранные монеты торгуются в портфельном режиме с теми же 10% на слот.

## 6. Какой вариант идёт в лидерборд (решается до holdout)

Для каждой стратегии по кривым WF-OOS:

- **Основной вариант = V0**, если только V1 или V2 не выполняет оба условия:
  - Шарп WF-OOS выше, чем у V0, минимум на 0.3;
  - лучше V0 минимум в 3 фолдах из 4.
- Если условиям удовлетворяют оба (V1 и V2), выбирается тот, у кого выше Шарп WF-OOS.

Логика: подбор параметров должен **заслужить** право заменить книжный вариант,
иначе мы просто подгоняемся под шум. Для большинства стратегий ожидаемо останется V0 — это нормально.

## 7. Финальная подгонка перед holdout

Для основного варианта V1/V2:
1. Повторить шаги 1–3 раздела 4 на **всём dev** (2023-01-01 → 2025-12-31).
2. Полученные параметры и монеты — это финальная конфигурация для holdout.

Для V0 финальная конфигурация = дефолты + весь пул.

## 8. Пререгистрация

Перед заморозкой для каждой стратегии создаётся `config/prereg/<ID>.yaml`:

```yaml
strategy_id: S02
strategy_version: 1.0.0
primary_variant: V0            # по правилу раздела 6
wf_oos_sharpe: {V0: 0.81, V1: 0.95, V2: 0.60}   # пример формата
folds_better_than_v0: {V1: 2, V2: 1}
final:
  V0: {params: {...}, tf: 1d, symbols: [...]}
  V1: {params: {...}, tf: 1d, symbols: [...]}
  V2: {params: {...}, tf: 1d, symbols: [...]}
n_trials_dev: 96               # из реестра
git_commit: <hash>
```

На holdout прогоняются **все три** варианта (так честнее, их результаты видны),
но место в лидерборде определяет `primary_variant`, выбранный заранее.

## 9. Учёт числа испытаний

- Все прогоны сетки на всех фолдах — испытания (тег `stage=wf`).
- DSR для WF-OOS считается с числом испытаний данной стратегии.
- DSR для holdout — с числом конфигураций, запущенных на holdout (`01_PROTOCOL`, раздел 9).
- Опционально (после основного пайплайна): Probability of Backtest Overfitting (PBO)
  по методу CSCV (Bailey, Borwein, López de Prado, Zhu) на матрице «конфигурация × подпериод».

## 10. Отчёт по оптимизации (`reports/wf/<ID>.md`)

- Число точек сетки, число испытаний, выбранные p* по фолдам (видно, стабильны ли параметры).
- Тепловые карты Шарпа по двум главным параметрам на train каждого фолда.
- Отобранные монеты по фолдам (видно, стабилен ли отбор).
- Кривые WF-OOS для V0 / V1 / V2 + бенчмарки + таблица по фолдам.
- Вывод простым языком: «оптимизация помогает / не помогает / вредит», «отбор монет
  устойчив / случаен», какой вариант основной и почему.

## 11. Честные оговорки

- 2023–2024 — в основном растущий рынок, 2026 — медвежий. Параметры, лучшие на росте,
  могут проиграть на падении. Walk-forward частично это покажет (2025 год смешанный),
  но не полностью.
- Если выбранные параметры сильно прыгают от фолда к фолду — это признак того,
  что оптимум случаен, и V0 надёжнее.
- Молодые монеты (короткая история) участвуют не во всех фолдах — отбор по ним менее надёжен.
